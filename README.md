# BPMN Rossilber

Визуальный редактор карт процессов в нотации SDCA / BPMN — как во вложенных примерах (`examples/`).

## Запуск

Это полностью клиентское приложение, без сборки.

```bash
# из корня репозитория
python3 -m http.server 8000
# открыть http://localhost:8000/index.html
```

Или разместите файлы на любом статическом хостинге (GitHub Pages, nginx и т.п.).

## Что внутри

- `index.html` — разметка интерфейса (хедер Rossilber, панель инструментов,
  палитра, холст, панель свойств, справочник).
- `styles.css` — фирменное оформление (navy-хедер, плитки цветов,
  сетка, toolbar, панель свойств, модальные окна, minimap).
- `app.js` — редактор (один файл, без зависимостей, ~1900 строк):
  состояние, 26 BPMN-фигур, рендер, палитра, drag&drop,
  выделение/перемещение/ресайз, pan/zoom, ортогональные соединители
  с развилками, inline-редактирование текста, undo/redo, копирование,
  экспорт JSON/SVG/PNG, minimap, горячие клавиши, автосохранение.

## Фигуры

- **События**: старт, промежуточное, конец, таймер.
- **Задачи**: обычная, критичная, ручная, автоматическая,
  задача другого отдела, подпроцесс.
- **Шлюзы**: «ИЛИ» (X), «И» (+), включающий (O), событийный (★).
  Позволяют развилки на 2-3-4 ветки.
- **Данные / системы**: Вход/Выход, Документ, IT-система / БД,
  Внешнее лицо, PI, KPI, SOP/OPL.
- **Контейнеры**: Пул, Дорожка, Группа (swimlanes).
- **Аннотации**: текстовая, заголовок уровня.

## Методология

Реализованы обозначения по методологии SDCA из `examples/`:
критичность элемента (жёлтый пунктир),
уровни 1-4 (Продукт / Процесс / Активность / Задача),
поля RACI, PI, KPI, SOP/OPL на каждом элементе,
три типа стрелок (поток управления / сообщений / ассоциация),
условные стрелки (ромбик в начале).

## Как соединять

Выделите фигуру — по её краям появляются 4 синих порта.
Потяните от любого порта к другой фигуре — создастся стрелка.
Для развилки — от одного шлюза можно создать 2-4 стрелки в разные фигуры.

## Экспорт

- **JSON** — полное состояние карты (нужен для повторного открытия).
- **BPMN 2.0 (.bpmn)** — OMG-стандарт для обмена между десктопной и браузерной
  версией, а также с Camunda Modeler / bpmn.io / Signavio и т.п.
  Координаты и размеры фигур сохраняются через `bpmndi:BPMNShape`.
  Кастомные поля SDCA (критичность, уровни, RACI, PI, KPI, методика) —
  в `extensionElements` под namespace `rossilber:`, другие инструменты их
  игнорируют, а наш редактор читает обратно без потерь.
- **SVG** — векторный экспорт для вставки в документы.
- **PNG** — 2×-растровый экспорт.

Автосохранение — раз в 5 сек в `localStorage`.

## Десктопная версия (Windows .exe)

Редактор также собирается в настольное Windows-приложение через Electron.
Код общий — десктоп грузит те же `index.html`/`styles.css`/`app.js`.

### Скачать готовую сборку

Файлы появляются в [GitHub Releases](../../releases) при каждом git-теге `v*`:

- `BPMN-Rossilber-<версия>-x64-nsis.exe` — инсталлятор (создаёт ярлыки,
  регистрирует деинсталлятор).
- `BPMN-Rossilber-<версия>-portable.exe` — портативный .exe,
  запускается без установки.

### Собрать локально

Нужен Node.js 20+ и Windows (или Windows-рантайм в CI).

```bash
cd desktop
npm install
npm run start      # быстрый запуск для разработки
npm run dist       # собрать installer + portable .exe в desktop/dist
```

### Совместимость файлов

Карта, сохранённая в **JSON** или **BPMN 2.0** в десктопе, полностью
совместима с браузерной версией и наоборот: координаты, размеры, цвета,
критичность, уровни, RACI, PI/KPI, методики/инструкции, подписи и
маршрутизация стрелок — всё сохраняется 1:1.

### CI (GitHub Actions)

Workflow `.github/workflows/build-desktop.yml` запускается при push-е
git-тега `v*` (например `v1.0.0`) на Windows-раннере и публикует оба
`.exe` в GitHub Releases.
